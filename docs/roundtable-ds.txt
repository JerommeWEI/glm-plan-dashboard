- 对齐现有"剩余递减"是对的：三个槽位都是 remaining、逆时针递减、虚线=无数据，第四槽不该引入新语法。

- `mode=unrestricted` 不要改环的线型（会与"虚线=无数据"撞车），只在详情卡文字体现（如 `无日限额`）；卡片可以放 `∞`，主轨 44px 放不下也不要放。

### P1 ② 周重置推算

- 风险：(a) **时区/DST**——`weekly_window_start` 带 `+08:00`，必须用 aware datetime 加法、并把展示时区固定成该 offset，不能用机器本地 naive 时间加 7 天（跨 DST 会差 1h，"重置 09-28 00:00" 显示成 23:00）；(b) **服务端语义是猜的**（样本 1 个）：可能懒更新，`window_start` 可能是上一窗口；(c) 边界——本地时钟越过推算重置点而服务端还没给新窗口时，绝不能把环置满或显示负数。
- 更稳妥做法，按重要性：
  1. **跨周期判定用 `window_start` 变化，不用本地时钟**：保留上一次 `window_start`，变了才认为新窗口（可触发回填动画）。本地推的时间只用于展示。
  2. 解析用 `datetime.fromisoformat`（3.11+ 直接吃 `+08:00`），保留 tzinfo；`reset = start + timedelta(days=7)` 在 aware 上做；比较用 UTC 时间戳。
  3. 用服务端字段优先：`weekly_window_start` 只用于展示；`expires_at=2027-05` 是**订阅到期**，千万别绑到环上。
  4. 合理性校验：`window_start` 未来 / 早于 7–8 天前 / `window_start+7d <= now` → 视为陈旧，卡片显示 `--`，环沿用上一读数（或虚线），不推算。
  5. 顺手修 `create_detail_image.reset_text`：它只输出 `h{m:02d}m`，周窗口会显示"重置 160h12m"，加一层 `>24h → N天Mh`。

## P0 · ③ 配置解析、安全与降级链

**最大风险不是解析失败，而是 key 外泄。** 现有 `_validated_usage_url` 的安全模型是"https + 三个写死的 GLM 域名 + DNS 全 IP 私网阻断"，这依赖 host 不可配置。Codex 的 host 来自用户可编辑的 `~/.codex/config.toml`，而 key 来自 `auth.json`——一旦"读 config.toml 的 base_url 就照发 key"，任何能改那个文件的东西都能拿到你的真实 key。

- **把 URL 与 key 的来源解耦**：widget 自己的 `config.json` 新增 `codex` 段（`base_url` + `trusted_hosts`，默认含 `uapi.ccwu.cc`）。只有 host 命中该段时才发 key；`config.toml` 的 base_url 只作**候选**，未授权就降级为"域名未授权"，绝不照发。这是唯一能挡住"config.toml 被改→key 被送到攻击者域名"的做法。
- **复用而非复制**校验：抽成 `_validated_url(base_domain, path, allowed_hosts)`，补 `ip.is_multicast or ip.is_unspecified`（现实现漏了组播）。现实现从 `urlsplit().hostname` 重建 URL，已正确丢掉 path/port/凭据，保持。DNS-rebinding 的 TOCTOU 现实现没处理——威胁模型是本地文件被改，性价比低，可不做。
- **tomllib 细节**：`tomllib.load(open(p,"rb"))`，捕 `TOMLDecodeError/OSError/PermissionError`（Codex CLI 正在写配置时会读到半截 → 0.3s 后重试一次）；尊重 `CODEX_HOME`；**provider 名别写死 `"OpenAI"`**——先读顶层 `model_provider` 再查 `model_providers[<name>]`。auth.json 的 key 可能带引号/已含 `Bearer ` 前缀，strip 后判前缀；401/403 时重读一次 auth.json（key 轮换）再判失败。**日志只打指纹**（`sk-****c4f2`）——现有 `print(f"API 错误: {exc}")` 不带 header，保持，别把请求对象整体打出来。注意 GLM 用的是裸 `Authorization: token`，Codex 要 `Bearer`，别复用。

## P1 · ② 周重置时刻推算

- 风险三条：**(a) 时区/DST**——`+08:00` 必须用 aware datetime，展示时区固定成该 offset，不能用机器本地 naive 时间加 7 天（跨 DST 会差 1h，把"09-28 00:00"显示成 23:00）；**(b) 服务端语义是猜的**（单样本）：可能懒更新，`window_start` 可能是上一窗口；**(c) 边界**——本地时钟越过推算点而服务端还没给新窗口时，绝不能把环置满或显示负数。
- 更稳妥，按重要性：
  1. **跨周期判定用 `window_start` 变化，不用本地时钟**：缓存上次值，变了才算新窗口（顺便触发回填动画）。本地推的时间只用于展示。

  3. 合理性校验：`window_start` 在未来 / 早于 7–8 天前 / `+7d <= now` → 视为陈旧，卡片 `--`，环沿用上一读数（或虚线），不推算。
  4. **`expires_at=2027-05` 是订阅到期，绝不能绑到环上**——这类字段很容易被顺手当"重置时间"用。
  5. 顺手修 `create_detail_image.reset_text`：它只输出 `h{m:02d}m`，周窗口会显示"重置 160h12m"，加 `>24h → N天Mh`。
