  ## P0 · 1) 圆环语义

  **周额度剩余比例是对的，建议采用，但要注意两点：**

  - 语义对齐成立：现有三槽都是"当前窗口剩余占比递减"，Codex 的周窗口是同构概念，只是窗口长度不同（7 天 vs 5 小时）。`remaining = (300-15.6)/300` 直接复用现有绘制逻辑即可，无需新代码路径。
  - 副作用要提前接受：周额度消耗慢，圆环一周内长期停在 90%+ 高位，视觉信息量低于 5h 槽。这是如实反映，不是问题——别为了"有动感"改用日用量。

  **daily_limit_usd=0 + mode=unrestricted 的表达：用今日已用 cost，但不进圆环。**

  - "不画"浪费了一个可用维度；"无限标记（∞）"在 44px 胶囊里辨识度差且暗示"随便用"，有误导性。
  - 推荐：圆环只承载周剩余%；今日 cost 放 hover 详情卡，显示为 `今日 $x.xx · 无上限`（unrestricted 时）或 `今日 $x.xx / $limit`。若想要环境态提示，可在槽位边缘加一个 2px 微点表示"今日有消耗"，不进环形语义。
  - 详情卡同时放月度 `103.3/1200`，一行文字即可，月额度用进度条而非第二个环。

  ## P0 · 3) 配置解析与降级链

  - tomllib（3.11+）读 config.toml、json 读 auth.json 的方案可行，记得 tomllib 必须 `open(..., "rb")`。
  - **降级链建议分四级，状态要可区分：**
    1. 文件缺失/字段缺失 → "未配置"态（槽位隐藏或灰色静态图标，**不轮询**，区别于故障）
    2. TOML/JSON 解析失败 → 同上按"未配置"处理并记日志
    3. 401/403 → "密钥失效"专属态（不同颜色角标），**退避重试**（如 30 分钟一次），避免每 5 分钟打失效 key 被中转站封 IP
    4. 网络不可达/超时/5xx/非 JSON → 走现有"虚线空环"约定
  - **URL 校验直接复用 GLM 那套**：强制 https、域名白名单加 `uapi.ccwu.cc`、DNS 解析后阻断私网/回环 IP。即使 URL 来自本地配置文件也值得做——配置文件可能被其他工具改写。另外加：3–5s 超时、禁止跟随重定向（或重定向目标同样过白名单）、响应体大小上限（如 64KB）。
  - 密钥脱敏：日志和 hover 卡都不出现 key，异常信息注意别把 Authorization 头带进堆栈输出。

  ## P1 · 2) 周重置时刻推算

  `window_start + 7d` 推算可行，风险与缓解：

  - **主要风险不是时区**（响应里带 `+08:00` 显式偏移，且国内无 DST），而是**中转站侧策略漂移**：账期调整、订阅续费导致窗口平移、服务器时钟偏差。推算是纯客户端行为，服务端变了你不知道。
  - **更稳妥的做法**：不要裸算"下次重置时刻"，而是做**过期检测**——若 `now >= window_start + 7d` 而响应里的 `window_start` 没更新，说明数据已过期，此时不显示推算的重置时间，标记"等待刷新"并立即触发一次重轮询。即：重置时间永远从**最新一次响应的 window_start** 派生，绝不跨周期沿用旧值。
  - 显示层用相对时间"约 x 天后重置"而非精确时刻，容忍小时级误差。

  ## P2 · 4) 布局

  - 44×232 → 约 307px 等间距加高：**合理，且是最不容易做坏的方案**——视觉节奏一致，hover 展开卡逻辑不用改。作为贴边悬浮轨，307px 在 1080p 屏幕上没问题。
  - 若担心小屏/多窗口场景，更优的顺序是：**压缩槽间距**（如 72→60px，4 槽约 270px）而不是缩环径（环 <28px 后弧线粗细和数字可读性都劣化）。
  - 不建议分组/折叠：4 个槽位远低于需要分组的复杂度阈值，反而增加交互层级。但建议顺手把槽位顺序和显隐做成配置项，为以后第 5 槽留余地。

  ## P3 · 5) 图标

  - "六圆叠加+中心打孔"在 12px 下**品牌辨识度很低**——花瓣交织结构完全糊掉，读出来是"一朵花/齿轮"，和 OpenAI 结形关联不上。这不是画法问题，是 12px 的物理极限。
  - 更实际的选择：放弃还原结形，用**高对比简洁剪影**——如六瓣极简花形（加大笔画宽度、不做交织）、或六边形轮廓+中心点、或直接用 "Cx" 字母。同时按 2–3x 尺寸用 PIL 渲染再降采样，保证 Win32 高 DPI 下边缘不毛糙。
